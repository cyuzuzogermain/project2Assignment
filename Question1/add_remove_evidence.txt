 add_remove_evidence.txt
 Evidence of dynamic memory behaviour and input validation for
 "Dynamic Academic Performance and Risk Analysis Engine"
 Build: gcc -Wall -Wextra -std=c11 -o engine main.c   -> 0 warnings
 Same run executed under ASan/UBSan (clang -fsanitize=address,
 -fsanitize=undefined): exit 0, no leaks, no invalid accesses.

 Values after "Choose an option" and after each prompt are the piped
 input echoed back by the program (pipes are not echoed by a terminal).
 Hidden menu option 0 (not listed in the menu) prints the internal array
 state: count = records held, capacity = records the realloc'ed array can
 hold; every realloc prints a [memory] line as it happens.
 Seeds: 12 records / capacity 16 (the array grew 4 -> 8 -> 16 while
 seeding).  Growth doubles the capacity; shrinking triggers when
 count < capacity/4 and halves the capacity (floor = initial 4).

--- Phases: (A) show state   (B) add 3        12 -> 15 records
            (C) remove 3     15 -> 12 records
            (D) add 3        12 -> 15 records
            (E) rejections: duplicate ID, grade > 100, non-numeric grade
        (three samples per example; none of the kept adds/removes
         crosses a realloc threshold, so only the seeding growth
         appears below)
